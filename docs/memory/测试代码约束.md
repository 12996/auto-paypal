# 测试代码约束

## 核心原则

**测试脚本必须调用 `index.js` 中的真实函数，而不是复制粘贴简化版代码。**
  使用方式

  # 正常运行（不保存 HTML）
  node test/xxx.js

  # 需要调试时，启用保存 HTML
  $env:DEBUG_MODE = "1"
  node test/xxx.js

  # 关闭调试
  $env:DEBUG_MODE = "0"

## 测试流程

### 1. 导出需要测试的函数

在 `index.js` 底部添加 `module.exports`，导出需要测试的函数：

```javascript
// index.js 底部
module.exports = {
    humanFillInput,
    fillZipAndCity,
    randomDelay,
    // ... 其他需要测试的函数
};
```

### 2. 测试脚本结构

```javascript
// test/test_xxx.js
const { chromium } = require('playwright');
const path = require('path');

// 直接导入 index.js 中的真实函数
const { humanFillInput, fillZipAndCity, randomDelay } = require('../index.js');

async function test() {
    const browser = await chromium.launch({ headless: false });
    const context = await browser.newContext();
    const page = await context.newPage();

    // 加载本地保存的 HTML 页面
    const htmlPath = path.resolve(__dirname, '../debug_html/xxx_error.html');
    await page.goto(`file://${htmlPath}`);

    // 调用 index.js 中的真实函数进行测试
    await humanFillInput(page, locator, 'test value', false, true);

    await browser.close();
}

test().catch(console.error);
```

### 3. 测试资源

- **HTML 页面来源**：`debug_html/` 目录下保存的错误页面快照
- **页面保存时机**：代码中 `debug.saveOnError(page, 'xxx')` 会在出错时自动保存

## 好处

1. **测试真实代码** - 不是简化版，发现的问题就是真实问题
2. **快速迭代** - 不用跑完整注册流程，直接用保存的页面测试
3. **修改即验证** - 修改 `index.js` 后，用同样的测试脚本立即验证

## 注意事项

1. 静态 HTML 页面无法模拟动态交互（如 AJAX 请求、iframe 内容）
2. 某些功能可能需要真实的网络环境才能完整测试
3. 导出函数时注意不要破坏 `index.js` 的正常运行逻辑
