# 2026-05-16 银行卡池改为卡密兑换结构

## 需求描述

后台银行卡池不再以银行卡号作为主入口，改为以卡密作为主入口：

- 批量导入只传入卡密，例如 `4859-F868-EMFMYMYY-B03E`。
- 卡密未兑换/未注册时，CARD/BILLING 字段显示为空白。
- 增加是否注册、是否激活、激活账号、兑换时间。
- 增加备注字段，用于记录卡密兑换失败、返回结构异常或其他未知错误。
- 已激活过账户的卡不再自动复用。

## 解决方案

- `card_assets` 表保留并扩展为卡密兑换资产表。
- 后台 UI 以 `card_key` 作为行唯一标识和选择/删除 key。
- 自动取卡只选择：
  - 已启用。
  - 已注册。
  - 未激活。
  - 卡号、有效期、CVC 均非空。
- 当没有已注册未激活可用卡时，运行时会从未注册 `card_key` 中预留一张，调用 `get_card_message.js` 兑换接口，写回 CARD/BILLING 后继续当前任务。
- 成品号流程激活成功后写入激活账号邮箱。
- 成品号流程和前台自助激活流程都先回写卡状态，再释放资产锁，避免并发任务短窗口内重复抢到同一卡。
- 卡资产禁用和成功次数统计优先按运行时预留行 `cardAssetId` 定位，其次兼容 `card_key`，最后才兼容旧 `card_number`。
- `remark` 用于保存失败原因或人工排查信息；兑换成功时应清空，兑换失败/异常时写入具体原因。
- 管理员可以在后台直接修改卡状态；`正常` 会恢复 `is_active=1`，`已报废` / `兑换异常` 会保持 `is_active=0`，避免异常卡被自动取用。
- 手机号池状态同样由管理员后台指定；激活流程遇到手机号拒绝或短信异常时只重试，不自动把手机号作废。
- 前台 token 激活流程无法拿到邮箱，只标记卡已激活。

## 修改文件

- `public/admin.html`
  - 表格字段、批量导入、添加行、保存 payload。
  - CARD/BILLING、激活账号、兑换时间、备注改为只读文本展示。
  - 卡状态改为管理员可编辑下拉：`正常` / `已报废` / `兑换异常`。
  - 兼容旧 `number` 结构，避免卡密列空白。
- `mysql-schema.sql`
  - 新建库时的 `card_assets` 表结构，包含 `remark TEXT NULL`。
- `mysql-store.js`
  - 字段归一化、后台读写、取卡条件、激活回写。
  - 后台读写保留 `remark` 字段。
  - 增加卡资产定位逻辑：`id` > `card_key` > `card_number`。
  - 增加未注册卡密预留、兑换成功写回、兑换失败写入备注。
  - `deleteCardAsset()` 支持按对象参数精确禁用卡，同时保留旧字符串参数兼容。
  - `incrementAssetSuccessCount()` 支持按 `cardAssetId` / `cardKey` / `cardNumber` 更新。
- `card_asset_registrar.js`
  - 封装运行时资产获取逻辑：优先使用已注册可用卡；没有可用卡时自动兑换未注册卡密。
  - 调用 `getCardMessage(key, { live: true })` 和 `formatCardForDatabase()`，把兑换结果转换并写回 `card_assets`。
  - 兑换失败时写入 `remark` 并禁用该卡，避免重复重试同一坏卡。
- `update-mysql-schema.js`
  - 旧库升级字段，补充 `remark TEXT NULL`。
- `server.js`
  - 前台激活成功后标记卡已激活。
  - 自助激活流程使用 `card_asset_registrar.js` 获取资产，并向 `index.js` 传递 CARD 与 BILLING 字段。
  - 自助激活成功时先标记 `is_activated=1` 并更新成功次数，再释放资产锁。
  - 自助激活中银行卡被拒时先按 `cardAssetId/cardKey/cardNumber` 禁用卡，再释放资产锁。
- `product_activator.js`
  - 成品号流程激活成功后标记卡已激活并记录账号邮箱。
  - 成品号流程使用 `card_asset_registrar.js` 获取资产，并向 `index.js` 传递 CARD 与 BILLING 字段。
  - 激活成功时先标记 `is_activated=1` 和 `activation_account`，再释放资产锁。
  - 银行卡被拒时先按 `cardAssetId/cardKey/cardNumber` 禁用卡，再释放资产锁。
- `test/test_card_assets_model.js`
  - 数据模型单元测试。
  - 覆盖自动取卡条件和卡资产定位优先级。
  - 覆盖管理员保存卡状态时 `status` 与 `is_active` 的归一化关系。
- `test/test_card_asset_registrar.js`
  - 覆盖已有可用卡不触发兑换。
  - 覆盖无可用卡时兑换未注册卡密、写回数据库字段并返回当前任务使用。
- `test/test_product_activator_asset_settlement.js`
  - 覆盖成品号流程中卡状态回写/禁用早于释放资产锁。
- `test/test_run_process_asset_settlement.js`
  - 覆盖前台自助激活流程中卡状态回写/禁用/成功次数更新早于释放资产锁。
- `test/test_card_admin_html_static.js`
  - 覆盖银行卡池后台需要展示并允许管理员编辑卡状态。

## 注意事项

- 旧数据会迁移为已注册卡，`card_key` 使用原 `card_number` 填充，避免已有可用卡立即失效。
- 当前真实卡密兑换逻辑已接入运行时资产获取；兑换成功时写入 `redeemed_at`，而不是在激活成功时写入。
- 兑换失败会设置 `status='兑换异常'` 并把接口返回、字段缺失或未知错误摘要写入 `remark`。
- `get_card_message.js` 的真实请求使用 `{ live: true }`，会请求外部兑换接口；测试默认使用 mock，不消耗真实卡密。
