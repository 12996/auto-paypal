# 代理测试统一化

**日期**: 2026-05-11  
**类型**: 功能改进

## 问题

原有的代理测试 API (`/api/admin/proxy/test`) 使用 `proxy-agent` 直连代理服务器，而本机网络环境需要先走 VPN 才能连接远程代理。

这导致：
1. 代理测试 API 直连会失败
2. 业务代码（Playwright）直连也会失败
3. 测试通过不代表业务能正常工作

## 解决方案

修改代理测试 API 和业务代码，统一使用 `local-proxy-bridge` 模块通过 VPN 链路连接。

**统一后的链路**:
```
测试/业务请求 → 本地代理桥接(:10808) → VPN(http://:7897) → 远程 SOCKS5 → 目标网站
```

## 修改的文件

### register_openai.js

1. **新增导入** (第9行):
```javascript
const { createProxyBridge, closeProxyBridge } = require('./local-proxy-bridge');
```

2. **启动 Playwright 前创建代理桥接**:
```javascript
if (proxyValue) {
    const bridge = await createProxyBridge({
        remoteProxy: proxyValue,
        localPort: 10808,
        vpnPort: 7897,
        useVpn: true,
        vpnType: 'http'
    });
    proxyBridgeStarted = true;
    launchOptions.proxy = { server: bridge.localProxy };
}
```

3. **成功/失败时关闭代理桥接**:
```javascript
if (proxyBridgeStarted) await closeProxyBridge();
```

### server.js

1. **重写代理测试 API** (`/api/admin/proxy/test`):
   - 移除 `proxy-agent` 直连方式
   - 改用 `local-proxy-bridge` 创建代理桥接
   - 使用 `socks-proxy-agent` 通过桥接后的本地代理进行测试
   - 串行测试，每个代理使用不同端口 (10900+) 避免冲突
   - 测试完成后自动关闭桥接

### package.json

新增依赖：`socks-proxy-agent`

## 测试方法

1. 确保 VPN 已启动并监听在 `:7897`
2. 启动服务器: `npm start`
3. 访问管理后台 http://localhost:3000
4. 在代理测试页面输入代理 URL 进行测试
5. 测试通过即表示业务也能正常使用该代理
