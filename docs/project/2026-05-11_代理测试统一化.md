# 代理测试统一化

**日期**: 2026-05-11  
**类型**: 功能改进

## 问题

原有的代理测试 API (`/api/admin/proxy/test`) 使用 `proxy-agent` 直连代理服务器，而业务代码（如 `register_openai.js`）使用 `local-proxy-bridge` 通过 VPN 链路连接。

这导致测试通过不代表业务能正常工作，因为两者走的网络路径不同。

## 解决方案

修改代理测试 API，让它也使用 `local-proxy-bridge` 模块，确保测试和业务使用完全相同的代码路径。

**统一后的链路**:
```
测试/业务请求 → 本地代理桥接 → VPN (:7897) → 远程 SOCKS5 → 目标网站
```

## 修改的文件

### server.js

1. **新增导入** (第15行):
```javascript
const { createProxyBridge, closeProxyBridge } = require('./local-proxy-bridge');
```

2. **重写代理测试 API** (`/api/admin/proxy/test`):
   - 移除 `proxy-agent` 直连方式
   - 改用 `local-proxy-bridge` 创建代理桥接
   - 使用 `socks-proxy-agent` 通过桥接后的本地代理进行测试
   - 串行测试，每个代理使用不同端口 (10900+) 避免冲突
   - 测试完成后自动关闭桥接

## 测试方法

1. 启动服务器: `npm start`
2. 访问管理后台 http://localhost:3000
3. 在代理测试页面输入代理 URL 进行测试
4. 测试通过即表示业务也能正常使用该代理
