# 浏览器指纹伪装库功能文档

## 概述

本项目的浏览器指纹伪装能力分为通用指纹库和加州 baseline 指纹库两类。当前支付自动化主流程优先使用 `lib/california-fingerprint.js`，目标是保持一套内部一致、接近真实美国加州 Windows Chrome 环境的指纹，而不是无约束随机。

核心原则：

- 真实性优先于随机性。
- 高层身份固定为美国加州、英文、Windows、Chrome。
- 低层噪声只做稳定微扰，避免同一页面多次读取得到不同结果。
- 指纹配置、HTTP 头、JS 运行时、PayPal locale 链路保持一致。

## 核心库文件

### `lib/browser-fingerprint.js` - 通用指纹伪装库

用于普通自动化场景的基础指纹伪装。

主要能力：

- 生成随机硬件配置。
- 清理常见自动化痕迹。
- 提供 Playwright `newContext()` 选项。
- 注入 navigator、screen、WebGL 等基础伪装脚本。

### `lib/california-fingerprint.js` - 加州 baseline 指纹库

当前主流程使用的高一致性 baseline 指纹。

固定画像：

```js
{
  region: 'San Diego',
  platform: 'Win32',
  platformName: 'Windows',
  hardwareConcurrency: 8,
  deviceMemory: 8,
  locale: 'en-US',
  languages: ['en-US', 'en'],
  timezone: 'America/Los_Angeles',
  screen: {
    width: 1920,
    height: 1080,
    availWidth: 1920,
    availHeight: 1032,
    colorDepth: 24,
    pixelDepth: 24
  },
  connection: {
    effectiveType: '4g',
    rtt: 100,
    downlink: 10,
    saveData: false
  },
  webgl: {
    vendor: 'Google Inc. (Intel)',
    renderer: 'ANGLE (Intel, Intel(R) UHD Graphics 620 Direct3D11 vs_5_0 ps_5_0, D3D11)'
  }
}
```

核心方法：

```js
CaliforniaFingerprint.generateRandomCaliforniaFingerprint(options)
CaliforniaFingerprint.generateMultipleCaliforniaFingerprints(count)
CaliforniaFingerprint.getPlaywrightOptions(config)
CaliforniaFingerprint.getSpoofingScript(config)
CaliforniaFingerprint.applyToPage(page, config)
CaliforniaFingerprint.applyToContext(context, config)
CaliforniaFingerprint.createCaliforniaContext(browser, customConfig)
```

说明：

- 方法名中仍保留 `Random`，但当前实现会固定为一套 San Diego baseline。
- 如传入 `zh-CN`、`zh` 等语言配置，会被 `forceEnglishConfig()` 强制改回 `en-US/en`。
- 当前 baseline 不再预授权 geolocation，避免与 PayPal 风控链路产生额外不一致。

### `lib/fingerprint-spoofer.js` - 高级指纹伪装库

用于更复杂或自定义程度更高的实验场景。

主要能力：

- 自定义硬件、屏幕、WebGL、语言、时区。
- 生成初始化脚本。
- 应用到 Playwright 页面或上下文。

## 加州 baseline 覆盖项

### 1. 自动化痕迹

处理项：

- `navigator.webdriver`
- `cdc_*` / `$cdc_*`
- `_phantom`
- `callPhantom`
- `webdriver-*`
- `driver-*`
- Playwright / Puppeteer 常见全局标记

### 2. 语言与地区

强制项：

```js
navigator.language === 'en-US'
navigator.languages === ['en-US', 'en']
Intl.DateTimeFormat().resolvedOptions().locale === 'en-US'
Accept-Language: en-US,en;q=0.9
timezoneId: America/Los_Angeles
```

相关代码：

- `CaliforniaFingerprint.ENGLISH_LOCALE`
- `CaliforniaFingerprint.ENGLISH_LANGUAGES`
- `CaliforniaFingerprint.forceEnglishConfig()`
- `CaliforniaFingerprint.getAcceptLanguageHeader()`

### 3. Client Hints / User-Agent

保持一致：

- `navigator.userAgent`
- `navigator.userAgentData.brands`
- `navigator.userAgentData.platform`
- `sec-ch-ua`
- `sec-ch-ua-mobile`
- `sec-ch-ua-platform`

Chrome 主版本会优先从真实浏览器版本读取，并同步到 UA 与 Client Hints。

### 4. 硬件与屏幕

固定为常见 Windows 桌面配置：

- CPU: 8 核
- 内存: 8GB
- 平台: `Win32`
- 触摸点: `0`
- 屏幕: `1920x1080`
- 可用高度: `1032`
- 色深: `24`

### 5. plugins / mimeTypes

在原生插件为空时，提供接近 Chrome PDF Viewer 的 PluginArray / MimeTypeArray 结构。

### 6. WebGL

采用 baseline 方式：

```js
HTMLCanvasElement.prototype.getContext -> returned gl.getParameter
```

不再使用直接替换 `WebGLRenderingContext.prototype.getParameter = new Proxy(...)` 的方式。这样更接近真实上下文实例行为，并降低原型层差异。

### 7. Canvas

处理项：

- `HTMLCanvasElement.prototype.toDataURL`
- `CanvasRenderingContext2D.prototype.getImageData`

策略：

- 只做极小像素级扰动。
- 使用 `fingerprintSeed` 生成稳定噪声。
- 避免每次读取都使用 `Math.random()`，防止同一页面内指纹漂移。

### 8. Audio

采用 baseline 方式：

```js
AudioContext / OfflineAudioContext prototype.createAnalyser
  -> returned analyser.getFloatFrequencyData
```

策略：

- 仅对 `getFloatFrequencyData()` 做微扰。
- 使用 seed 稳定噪声，避免同会话内随机跳变。

### 9. permissions / Notification

处理项：

- `navigator.permissions.query`
- `Notification.permission`

目标：

- notifications 返回 `default` 或 prompt 风格结果。
- 避免 headless 环境中过早暴露 `denied`。

### 10. iframe

对动态创建的 iframe 处理：

- hook `Document.prototype.createElement`
- 在 `iframe.contentWindow.navigator` 上补充 `webdriver === undefined`

## PayPal 英文/美国链路补强

主流程除指纹库外，还在以下文件补强 PayPal 语言与地区链路：

- `index.js`
- `chatgpt.js`

处理项：

- 订单 API 请求头加入 `Accept-Language: en-US,en;q=0.9`。
- PayPal document 请求强制 `accept-language`。
- PayPal URL 强制追加/覆盖：
  - `locale.x=en_US`
  - `country.x=US`
  - `lang=en_US`
  - `language=en_US`
  - `hl=en`
- 预设 PayPal cookie：
  - `LANG=en_US%3BUS`
  - `cookie_check=yes`
- 运行时打印 `[PayPal Locale]` 诊断日志，确认最终页面语言来源。

## 配置一致性检查

`validateFingerprintConsistency(config, options)` 会检查：

- UA Chrome major 是否与 `config.chromeMajor` 一致。
- `Accept-Language` 是否为英文 baseline。
- Playwright `locale` 是否为 `en-US`。
- `timezoneId` 是否与配置一致。
- 是否错误预授权 geolocation。

## 注意事项

1. 指纹脚本必须在页面导航前注入。
2. 更新代码后必须重启 Node / 浏览器进程。
3. PayPal 页面语言不只由 `navigator.language` 决定，还可能来自 URL、cookie、订单 session 和服务端渲染。
4. 如果 JS 层为英文但 PayPal 仍中文，需要优先检查：
   - 最终 URL 是否包含中文 locale。
   - 页面 `document.documentElement.lang`。
   - PayPal cookie `LANG`。
   - 外部订单接口返回的支付链接是否已绑定地区。
